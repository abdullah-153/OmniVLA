OmniVLA: Perception Engine

Document 02 — Comprehensive Perception Strategy

1. The Perception Problem

The perception module must answer one question: "What is on the screen right now, described in ≤200 tokens?"

This is the most critical module in the entire pipeline. If perception fails, every downstream module fails. The challenge is threefold:

  1. Completeness: Capture ALL interactive elements the user might need to click
  2. Accuracy: Label each element correctly (button vs. label vs. text field)
  3. Efficiency: Do it in <150ms without touching the GPU

Why Existing Approaches Fail for Perception

Approach Failure Mode
Raw screenshot to VLM Requires vision encoder on GPU (~1-2GB). Can't co-exist with reasoning LLM on 6GB.
YOLO object detection Misses custom UI elements. Can't detect text-only buttons. Requires training data for each UI toolkit.
OCR-only Can see text but can't distinguish buttons from labels. No understanding of UI hierarchy.
UI tree dump Too verbose (500+ nodes). Many elements hidden. Tree structure overwhelms small LLMs.

Our solution: A tiered fusion strategy that uses the right tool for each situation.

3. Tier 1: UIA-First Perception (Detailed)

3.1 Why UIA is Superior

Windows UI Automation (UIA) is an accessibility API that exposes the entire UI element tree of most applications. It provides:

  • Exact bounding boxes — pixel-perfect coordinates, no estimation
  • Semantic types — Button, TextBox, MenuItem, TabItem, CheckBox, etc.
  • Accessible names — The text/label of each element
  • States — Enabled, disabled, focused, selected, expanded
  • Control patterns — InvokePattern (click), ValuePattern (type), SelectionPattern (choose)

This means: For native Windows apps, we can identify every interactive element with zero inference cost. No model needed.

3.2 UIA Implementation

import pywinauto
from pywinauto import Desktop

class UIAExtractor:
    """Extract interactive elements from the active window using UIA."""

    # Element types we care about
    INTERACTIVE_TYPES = {
        "Button", "Edit", "ComboBox", "CheckBox", "RadioButton",
        "MenuItem", "TabItem", "Hyperlink", "ListItem", "TreeItem",
        "Slider", "Spinner", "DataItem", "ToolBar", "MenuBar"
    }

    def extract(self, max_elements: int = 20) -> list[dict]:
        """Get interactive elements from the foreground window."""
        try:
            # Connect to the active window
            app = Desktop(backend="uia")
            window = app.window(active_only=True)

            # Walk the element tree (depth-limited for performance)
            elements = []
            self._walk_tree(window.wrapper_object(), elements, 
                          max_depth=6, max_elements=max_elements)

            return elements

        except Exception as e:
            logger.warning("UIA extraction failed: %s", e)
            return []

    def _walk_tree(self, element, results, depth=0, 
                   max_depth=6, max_elements=20):
        """Recursively walk the UIA tree, collecting interactive elements."""
        if depth > max_depth or len(results) >= max_elements:
            return

        try:
            control_type = element.element_info.control_type
            name = element.element_info.name or ""

            # Only collect interactive elements with visible names
            if (control_type in self.INTERACTIVE_TYPES 
                and name.strip() 
                and element.is_visible()):

                rect = element.rectangle()
                results.append({
                    "type": self._map_type(control_type),
                    "label": name[:60],
                    "bbox": (rect.left, rect.top, rect.right, rect.bottom),
                    "center": (rect.mid_point().x, rect.mid_point().y),
                    "enabled": element.is_enabled(),
                    "source": "uia",
                    "uia_handle": element.handle,  # For direct invocation
                })

            # Recurse into children
            for child in element.children():
                self._walk_tree(child, results, depth + 1, 
                              max_depth, max_elements)

        except Exception:
            pass  # Skip inaccessible elements

    @staticmethod
    def _map_type(uia_type: str) -> str:
        """Map UIA control types to our simplified type system."""
        mapping = {
            "Button": "button",
            "Edit": "text_field",
            "ComboBox": "dropdown",
            "CheckBox": "checkbox",
            "RadioButton": "radio",
            "MenuItem": "menu_item",
            "TabItem": "tab",
            "Hyperlink": "link",
            "ListItem": "list_item",
            "TreeItem": "tree_item",
        }
        return mapping.get(uia_type, "label")

4. Tier 2: OCR Fallback (Detailed)

4.1 When OCR is Needed

OCR is activated when:

  1. UIA returns fewer than 3 interactive elements for a visible window
  2. The active application is known to be UIA-opaque (e.g., games, remote desktop)
  3. The user explicitly requests visual perception mode

4.2 OCR Configuration

class OCREngine:
    """CPU-based OCR for text extraction from screenshots."""

    def __init__(self, engine="easyocr", lang="en"):
        if engine == "easyocr":
            import easyocr
            self.reader = easyocr.Reader([lang], gpu=False)
        elif engine == "paddleocr":
            from paddleocr import PaddleOCR
            self.reader = PaddleOCR(use_angle_cls=True, lang=lang, 
                                     use_gpu=False, show_log=False)

    def extract(self, image, scale=0.5):
        """Extract text with downscaling for speed."""
        # Downscale for speed (UI text is large, survives downscaling)
        small = resize(image, scale)
        results = self.reader.readtext(small)

        # Scale coordinates back
        return [scale_coords(r, 1/scale) for r in results 
                if r.confidence > 0.3]

4.3 Element Type Heuristics (from OCR)

When we only have OCR text and bounding boxes, we must guess the element type:

BUTTON_WORDS = {
    "ok", "cancel", "save", "close", "apply", "submit", "send",
    "next", "back", "yes", "no", "delete", "edit", "new", "open",
    "sign in", "log in", "sign up", "search", "compose", "reply",
    "forward", "browse", "upload", "download", "create", "add",
    "remove", "update", "refresh", "print", "copy", "paste",
    "cut", "undo", "redo", "done", "finish", "continue",
}

def guess_element_type(text: str, bbox, screen_position) -> str:
    text_lower = text.strip().lower()
    width = bbox[2] - bbox[0]
    height = bbox[3] - bbox[1]
    aspect = width / max(height, 1)

    # Short text in compact box = likely button
    if len(text_lower) <= 20 and height < 50:
        if text_lower in BUTTON_WORDS:
            return "button"
        if aspect > 2.0 and aspect < 8.0:
            return "button"  # Wide-ish, short = button shape

    # URL patterns = link
    if text_lower.startswith(("http", "www.")):
        return "link"

    # At top of screen, short text = tab
    if screen_position[1] < 100 and len(text_lower) <= 25:
        return "tab"

    # Tall narrow box or contains cursor-like artifacts = text field
    if height > 25 and width > 150 and len(text_lower) < 5:
        return "text_field"

    # Single character or icon-like = icon
    if len(text_lower) <= 2:
        return "icon"

    return "label"

5. Tier 3: YOLO Detection (Optional)

5.1 When YOLO Adds Value

YOLO is useful for detecting visual-only UI elements that have no text:

  • Close/minimize/maximize buttons (the × ○ □ window controls)
  • Icon-only toolbar buttons (no text labels)
  • Image thumbnails that are clickable
  • Scrollbars, sliders, and other non-text controls

5.3 Custom Training Considerations

Pre-trained YOLO models are trained on natural images, not UI screenshots. For best results:

  • Fine-tune on UI element datasets (OmniAct, Rico, SeeClick-Pretrain)
  • Target classes: button, input, icon, checkbox, dropdown, scrollbar, slider
  • Training data: ~5000 annotated UI screenshots (available from HuggingFace)

6. Fusion Strategy: Combining Tiers

6.1 Element Deduplication

When multiple tiers detect the same element, we need to merge them:

def fuse_elements(uia_elements, ocr_elements, yolo_elements):
    """Merge elements from all sources, removing duplicates."""
    all_elements = []

    # UIA elements are highest priority
    all_elements.extend(uia_elements)

    # Add OCR elements that don't overlap with UIA
    for ocr_el in ocr_elements:
        if not any(bbox_overlap(ocr_el.bbox, uia_el.bbox) > 0.5 
                   for uia_el in uia_elements):
            all_elements.append(ocr_el)

    # Add YOLO elements that don't overlap with existing
    for yolo_el in yolo_elements:
        if not any(bbox_overlap(yolo_el.bbox, el.bbox) > 0.5 
                   for el in all_elements):
            all_elements.append(yolo_el)

    # Sort by reading order (top-to-bottom, left-to-right)
    all_elements.sort(key=lambda e: (e.bbox[1] // 30, e.bbox[0]))

    # Assign sequential IDs
    for i, el in enumerate(all_elements):
        el.id = i + 1

    return all_elements[:20]  # Cap at 20 for token budget

def bbox_overlap(a, b):
    """Compute IoU (Intersection over Union) of two bounding boxes."""
    x1 = max(a[0], b[0])
    y1 = max(a[1], b[1])
    x2 = min(a[2], b[2])
    y2 = min(a[3], b[3])

    intersection = max(0, x2-x1) * max(0, y2-y1)
    area_a = (a[2]-a[0]) * (a[3]-a[1])
    area_b = (b[2]-b[0]) * (b[3]-b[1])
    union = area_a + area_b - intersection

    return intersection / max(union, 1)

6.2 Adaptive Tier Selection

def perceive(self) -> SemanticState:
    """Adaptive perception: use the cheapest tier that provides sufficient coverage."""

    # Always start with UIA
    uia_elements = self.uia.extract(max_elements=20)

    if len(uia_elements) >= 5:
        # UIA provided good coverage — skip OCR
        elements = uia_elements
        logger.info("UIA-only perception: %d elements", len(elements))
    else:
        # UIA insufficient — activate OCR
        frame = self.capture.capture()
        ocr_results = self.ocr.extract_downscaled(frame.pixels, scale=0.5)
        ocr_elements = self._build_elements_from_ocr(ocr_results)
        elements = fuse_elements(uia_elements, ocr_elements, [])
        logger.info("Hybrid perception: %d UIA + %d OCR = %d elements",
                    len(uia_elements), len(ocr_elements), len(elements))

    # Build and return semantic state
    return self._build_state(elements)

8. Edge Cases & Solutions

8.1 Dynamic Content

Problem: Web pages and apps with dynamic content (loading spinners, animations, lazy-loaded elements).

Solution:

  • Implement a "stability check": capture twice with 300ms gap, compare. If SSIM > 0.95, content is stable.
  • If content is still loading (spinner detected via OCR or YOLO), wait up to 3 seconds before proceiving.

8.2 Multi-Monitor

Problem: User might have multiple monitors.

Solution:

  • Always capture the monitor containing the active window.
  • Use mss monitor enumeration + Win32 MonitorFromWindow to identify the correct monitor.

8.3 High-DPI / Scaling

Problem: Windows DPI scaling (125%, 150%, 200%) causes coordinate mismatches.

Solution:

  • Use DPI-aware APIs: call SetProcessDPIAware() at startup.
  • UIA bounding boxes are already in physical pixels (DPI-adjusted).
  • OCR coordinates from mss captures are also in physical pixels.

8.4 Overlapping Elements

Problem: Dropdown menus, tooltips, and popups overlay main content.

Solution:

  • Detect overlays via UIA (popup/tooltip elements have special properties).
  • When a menu is detected, only report menu items as interactive elements.
  • Set is_menu_open: true or is_dialog: true flag so the LLM knows to interact with the overlay.

9. Performance Optimization

9.1 Lazy OCR Loading

OCR models (EasyOCR/PaddleOCR) take ~5 seconds to load on first use. Pre-load at agent startup:

# At startup, trigger lazy load
threading.Thread(target=self.ocr._ensure_loaded, daemon=True).start()

9.2 Frame Caching

Don't re-capture the screen if less than 100ms has passed since the last capture. Cache the frame and re-use it.

9.3 ROI (Region of Interest) Capture

For sub-goal-specific perception, only capture and OCR the relevant region:

# If we know we're looking for an element in the toolbar:
toolbar_frame = self.capture.capture_region(0, 0, 1920, 120)
ocr_results = self.ocr.extract(toolbar_frame.pixels)

This reduces OCR time by 60-80% for localized tasks.
