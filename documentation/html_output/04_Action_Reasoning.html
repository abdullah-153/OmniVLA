OmniVLA: Action Reasoning

Document 04 — Constrained LLM Decision Making

1. The Action Reasoning Problem

Given a sub-goal and the current semantic state, the Action Reasoner must select exactly one valid action. This is the module where the LLM's intelligence is most directly applied — and where hallucination risk is highest.

The Challenge

Sub-goal: "Click the Compose button"

Semantic State:
  [1] button: "Compose" (top-left)
  [2] tab: "Inbox" (top-left)
  [3] tab: "Sent" (top-left)
  [4] label: "Primary" (top-center)
  [5] button: "Search" (top-right)

Expected output: click(1)

What a hallucinating model might output:
  - "I'll click the compose button at coordinates (150, 300)"  ← Wrong format
  - "click(compose)"                                           ← Wrong ID format
  - "The compose button is element 2"                          ← Wrong element
  - "First, let me think about..."                              ← Too verbose

Solution: Constrained decoding via GBNF grammar makes it physically impossible for the model to produce anything except valid action syntax.

2. GBNF Constrained Decoding

2.1 What is GBNF?

GBNF (GGML BNF) is a grammar specification format used by llama.cpp to constrain the model's output to match a specific format. At each token generation step, the model's logits are masked so only tokens that would produce a valid next character according to the grammar are considered.

Result: The model literally cannot hallucinate malformed output. Every generated token is guaranteed to be part of a syntactically valid action.

2.2 The Action Grammar

# OmniVLA Action Grammar (GBNF)
# Guarantees structurally valid action output

root ::= thought action

# Brief reasoning (max 200 chars) — gives the model "thinking" space
thought ::= "THINK: " thought-text "\n"
thought-text ::= [^\n]{1,200}

# One of seven possible action types
action ::= click-action 
         | type-action 
         | key-action 
         | scroll-action 
         | wait-action 
         | done-action 
         | fail-action

# Click an element by its numeric ID from the semantic state
click-action ::= "ACTION: click(" element-id ")\n"

# Type text into the currently focused text field
type-action ::= "ACTION: type(\"" type-content "\")\n"

# Press a keyboard shortcut
key-action ::= "ACTION: key(" key-combo ")\n"

# Scroll the page
scroll-action ::= "ACTION: scroll(" direction "," ws amount ")\n"

# Wait for UI to update
wait-action ::= "ACTION: wait(" wait-seconds ")\n"

# Signal sub-goal completion
done-action ::= "ACTION: done()\n"

# Signal impossible sub-goal with explanation
fail-action ::= "ACTION: fail(\"" fail-reason "\")\n"

# Primitives
element-id ::= [1-9] [0-9]?                    # 1-99
type-content ::= [^"]{1,500}                     # Any text up to 500 chars
fail-reason ::= [^"]{1,200}                      # Explanation
key-combo ::= key-name ("+" key-name)*           # e.g., ctrl+shift+s
key-name ::= "ctrl" | "alt" | "shift" | "enter" | "tab" | "escape" 
           | "space" | "backspace" | "delete" | "home" | "end" 
           | "pageup" | "pagedown" | "up" | "down" | "left" | "right"
           | "f1" | "f2" | "f3" | "f4" | "f5" | "f6" 
           | "f7" | "f8" | "f9" | "f10" | "f11" | "f12" 
           | letter | digit
letter ::= [a-z]
digit ::= [0-9]
direction ::= "up" | "down" | "left" | "right"
amount ::= [1-9] [0-9]?
wait-seconds ::= [1-5]
ws ::= " "?

2.3 What This Prevents

Hallucination Type Without Grammar With Grammar
Invalid action names "press(Enter)" — unrecognized ❌ Impossible — only 7 action types allowed
Wrong argument format "click(compose)" — not a number ❌ Impossible — only digits after click(
Missing quotes "type(hello)" — no quotes ❌ Impossible — " required by grammar
Rambling output "Let me think about this more..." ❌ Impossible — must end with \n after action
Multiple actions "click(1) and then type('hi')" ❌ Impossible — grammar only allows one action
No action at all "I can't figure this out" ❌ Impossible — must output THINK + ACTION

3. The Reasoning Prompt

3.1 System Prompt

You are a GUI automation agent operating on Windows.
You see a compressed description of the current screen state.
You must complete the given sub-goal by choosing ONE action.

RULES:
1. THINK briefly about what to do (max 1 sentence).
2. Choose the best ACTION from the available types:
   - click(id)     — Click an element by its numeric ID
   - type("text")  — Type text into the currently focused field
   - key(combo)    — Press a keyboard shortcut (e.g., ctrl+s)
   - scroll(dir,n) — Scroll: up/down/left/right, 1-99 clicks
   - wait(s)       — Wait 1-5 seconds for UI to update
   - done()        — Current sub-goal is complete
   - fail("why")   — Sub-goal is impossible, explain why
3. Use element IDs from the state to click. 
4. PREFER keyboard shortcuts when they are faster/more reliable.
5. Output done() when the sub-goal IS ALREADY complete in the current state.
6. Output fail() ONLY if the sub-goal is truly impossible.
7. If an element is not visible, try scrolling to find it.

CURRENT SUB-GOAL: {goal}

{semantic_state}

{memory_context}

Choose your action:

4. Reasoning Strategies

4.1 Direct Match

The simplest case: the sub-goal mentions an element name that exactly matches a state element.

Goal: "Click the Save button"
State: [3] button: "Save" (bottom-right)
→ THINK: Save button is element 3.
→ ACTION: click(3)

4.2 Semantic Match

The sub-goal describes intent, not an exact element name:

Goal: "Open a new document"
State: [1] menu: "File" (top-left)
→ THINK: Need to open File menu to find New option.
→ ACTION: click(1)

4.3 Shortcut Override

The goal can be achieved faster via keyboard:

Goal: "Save the current file"
State: [1] menu: "File" (top-left), [12] button: "Save" (top-left)
→ THINK: Ctrl+S is faster and more reliable than clicking.
→ ACTION: key(ctrl+s)

4.4 State Completion

The sub-goal is already satisfied in the current state:

Goal: "Open the Home tab"
State: [2] tab: "Home" (top-left) — ALREADY SELECTED
→ THINK: Home tab is already selected/active.
→ ACTION: done()

4.5 Element Not Visible

The target element might be off-screen:

Goal: "Click the Submit button at the bottom"
State: (no Submit button visible)
→ THINK: Submit button not visible, need to scroll down.
→ ACTION: scroll(down, 5)

5. Prompt Engineering for Small Models

5.1 Key Principles for 3-4B Models

Principle Why Implementation
Short context Small models lose coherence with long prompts Keep total prompt under 400 tokens
Explicit formatting Models follow format better when shown Include format example in system prompt
Numbered elements Sequential IDs are easier than names [1] button: "Save" format
One decision Don't ask for reasoning AND action Grammar forces THINK (brief) + ACTION (structured)
Memory as examples Few-shot improves accuracy dramatically Inject 1-2 past successful actions
Avoid negatives "Don't click X" confuses small models Say "Click Y instead"
Region hints Spatial hints help disambiguation (top-left), (center), etc.

5.2 Prompt Token Budget

System prompt:                     ~150 tokens
Sub-goal:                          ~20 tokens
Semantic state:                    ~150 tokens
Memory context:                    ~50 tokens
"Choose your action:":             ~3 tokens
────────────────────────────────────────────
TOTAL INPUT:                       ~373 tokens
OUTPUT (THINK + ACTION):           ~30-50 tokens
────────────────────────────────────────────
TOTAL:                             ~420 tokens

Context window (2048):             ~1600 tokens remaining

Plenty of headroom. The model never has to work near its context limit.

6. Action Parsing

After the LLM generates output, we parse the constrained text:

import re

_ACTION_PATTERNS = {
    "click":  re.compile(r'click\((\d+)\)'),
    "type":   re.compile(r'type\("([^"]*)"\)'),
    "key":    re.compile(r'key\(([^)]+)\)'),
    "scroll": re.compile(r'scroll\((\w+),\s*(\d+)\)'),
    "wait":   re.compile(r'wait\((\d+)\)'),
    "done":   re.compile(r'done\(\)'),
    "fail":   re.compile(r'fail\("([^"]*)"\)'),
}

def parse_action(raw: str) -> AgentAction:
    """Parse GBNF-constrained output into structured action."""
    # Extract thought
    thought = ""
    think_match = re.search(r'THINK:\s*(.+)', raw)
    if think_match:
        thought = think_match.group(1).strip()

    # Extract action
    action_match = re.search(r'ACTION:\s*(.+)', raw)
    if not action_match:
        return AgentAction("fail", ["Could not parse"], thought, raw)

    action_str = action_match.group(1).strip()

    for action_type, pattern in _ACTION_PATTERNS.items():
        m = pattern.search(action_str)
        if m:
            return AgentAction(action_type, list(m.groups()), thought, raw)

    return AgentAction("fail", ["Unknown action format"], thought, raw)

Because the grammar constrains output, this parser should always succeed. The fallback is purely defensive.

7. Confidence & Calibration

7.1 Using Log Probabilities

llama.cpp can return log probabilities for generated tokens. We can use these to estimate the model's confidence:

def get_action_confidence(llm_response) -> float:
    """Estimate model confidence from token log probabilities."""
    if not llm_response.get("logprobs"):
        return 0.5  # Unknown confidence

    action_logprobs = []
    in_action = False

    for token_info in llm_response["logprobs"]:
        if "ACTION:" in token_info["token"]:
            in_action = True
        if in_action:
            action_logprobs.append(token_info["logprob"])

    if not action_logprobs:
        return 0.5

    # Average log probability → confidence
    avg_logprob = sum(action_logprobs) / len(action_logprobs)
    confidence = math.exp(avg_logprob)  # Convert from log space

    return confidence

7.2 Confidence-Based Retry

def reason_with_confidence(self, goal, state, memory):
    """Reason with confidence checking. Retry if low confidence."""

    action, confidence = self._reason_once(goal, state, memory)

    if confidence > 0.7:
        return action  # High confidence — proceed

    if confidence > 0.4:
        # Medium confidence — retry with lower temperature
        action2, conf2 = self._reason_once(goal, state, memory, temp=0.1)
        return action2 if conf2 > confidence else action

    # Low confidence — add explicit disambiguation to prompt
    disambiguation = self._add_disambiguation(goal, state)
    return self._reason_once(goal, state, memory + disambiguation)

8. Common Failure Modes & Mitigations

8.1 Wrong Element ID

Problem: Model selects element 3 when element 7 is correct.

Mitigation:

  • Use descriptive labels: [3] button: "Print" is better than [3] button
  • Include region hints: (top-right) helps spatial disambiguation
  • Memory: if the same goal succeeded with element 7 before, prefer it

8.2 Premature done()

Problem: Model says done() before the sub-goal is actually complete.

Mitigation:

  • Semantic verification catches this: if the expected outcome isn't in the new state, don't accept done()
  • Add explicit completion criteria in the prompt: "Output done() ONLY when you can see that [specific outcome] has occurred"

8.3 Infinite Scroll Loop

Problem: Model keeps scrolling because it can't find an element that doesn't exist.

Mitigation:

  • Maximum 5 actions per sub-goal
  • If 3+ consecutive scrolls with no state change, output fail("element not found")
  • Re-plan logic catches this and tries alternative approaches

8.4 Type in Wrong Field

Problem: Model outputs type("hello") but the wrong text field is focused.

Mitigation:

  • Always click(text_field_id) before type("text")
  • The decomposer should include "Click the search field" before "Type the query"
